### Project Brief: **Bank Account Management System**

#### **Overview**
You are tasked with developing a **Bank Account Management System** that simulates multiple bank accounts. The system should allow account holders to perform typical banking operations, including deposits, withdrawals, balance checking, and transfers between accounts.

The bank account system must also include validation for account holders based on their residential region, specifically **Indian residents**. The validation should verify if the account holder’s IBAN (International Bank Account Number) or SWIFT code matches the criteria for a valid account.

---

#### **Key Functional Requirements**

1. **Account Holder Information**
   - Each account should store the following information:
     - Account Holder's Name
     - Account Number
     - Account Type (e.g., Saving/Checking)
     - Balance (starting with Rs. 0)
     - IBAN/SWIFT Number
     - Residential Region (used to validate the account)
  
2. **Account Operations**
   - **Deposit**: Method to add money to the account balance.
   - **Withdraw**: Method to withdraw money from the account.
   - **Check Balance**: Method to check the current balance in the account.
   - **Mini-Balance**: Method that prints a brief balance summary (e.g., Rs. 100 or Rs. 200).

3. **Account Validation (Regional Verification)**
   - The system should check if the account holder’s **IBAN/SWIFT number** is valid for Indian account holders. It should verify whether the account number starts with "IN" (or a similar pattern) to indicate it’s a valid Indian resident account holder.

4. **Transfer between Accounts**
   - The system must support the **transfer of funds** from one account to another, ensuring that:
     - The sender account has sufficient balance for the transfer.
     - Both accounts must exist within the system.
   
5. **Storing Accounts**
   - All accounts should be stored in a global **array** to maintain a record of all created accounts. New accounts can be created dynamically by the system.
   
6. **Error Handling**
   - **Invalid IBAN/SWIFT**: If an invalid account number is provided during account creation or transfer, the system should show an appropriate error message.
   - **Insufficient Funds**: If an account holder tries to withdraw or transfer more than the available balance, an error message should be shown.

---

#### **Project Design Approach**

##### **Step 1: Define the BankAccount Class**
1. Create a class `BankAccount` that will represent individual bank accounts.
2. Define the following properties for the class:
   - **Account holder’s name**
   - **Account number**
   - **IBAN/SWIFT number**
   - **Balance**
3. Define methods inside the class to perform the operations:
   - **deposit(amount)**: Add money to the account balance.
   - **withdraw(amount)**: Deduct money from the account balance.
   - **getBalance()**: Return the current balance.
   - **miniStatement()**: Print a summary like Rs. 100 or Rs. 200.
   - **transferTo(anotherAccount, amount)**: Transfer money between two accounts.
   - **validateAccount()**: Check if the account is valid based on the IBAN/SWIFT format.

##### **Step 2: Create the Account Management System**
1. **Account Creation**: Implement a function or a method in another class (e.g., `BankSystem`) to manage creating new accounts.
   - When creating an account, check the **IBAN/SWIFT number** for validity (the pattern "IN" for Indian residents).
   - If the account is invalid, an error message should be thrown or logged.
   
2. **Account Array**: Maintain an array that stores all created bank accounts. This array should allow:
   - **Accessing existing accounts** by account number.
   - **Adding new accounts** when new account holders sign up.

##### **Step 3: Implement Bank Operations (Using Methods)**
1. **Deposits and Withdrawals**:
   - Each account should allow deposits and withdrawals.
   - You should handle basic validations like:
     - Ensuring deposits and withdrawals do not exceed available balance.
   
2. **Transfer**:
   - Implement the transfer functionality so that one account can send money to another.
   - The sender account should verify the balance before the transaction occurs.

##### **Step 4: Error Handling**
1. **Invalid Account**: Ensure that any attempt to create an account with an invalid IBAN/SWIFT number results in an appropriate error message.
2. **Insufficient Funds**: If a withdrawal or transfer amount exceeds the balance, show an error message.

##### **Step 5: Testing and Debugging**
1. **Test the Account Creation**: Ensure accounts are correctly created and validated with proper IBAN/SWIFT validation.
2. **Test Deposits and Withdrawals**: Ensure deposits and withdrawals work correctly, including balance checks.
3. **Test Transfers**: Test the transfer functionality between multiple accounts.
4. **Handle Errors Gracefully**: Ensure that invalid operations (e.g., insufficient balance) result in correct error messages.

---

#### **Design Principles to Follow**
1. **Modularization**: Break down the project into smaller components, focusing on each class and method to avoid a bloated codebase. Keep your functions small and focused.
2. **Data Encapsulation**: Make account properties like balance and IBAN private, and expose only necessary methods (via getters/setters).
3. **Code Reusability**: Design your methods to be reusable across various accounts (e.g., same deposit and withdraw methods for all accounts).
4. **Error Handling**: Always include error handling for invalid inputs (invalid IBAN/SWIFT, withdrawal exceeding balance).
5. **Testing**: Create unit tests for your methods to ensure everything works as expected.

---

#### **Final Deliverables**
1. **BankAccount Class**: Contains methods to manage the individual account operations.
2. **BankSystem Class**: Manages the creation of new accounts and stores them in an array.
3. **Main Program**: A main entry point (e.g., `index.js`) where the user interacts with the bank system to create accounts, deposit, withdraw, check balances, and transfer money.
4. **Documentation**: Clear documentation of the project, including how each method works and expected input/output.
